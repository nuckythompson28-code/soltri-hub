🛡️ 통행권 가드 — 원리와 적용

CNC 매크로 중간시작 사고 방지 표준 · Soltri · 최초 2026-06-12 사고 후 도입 · 문서화 2026-07-23

1. 왜 필요한가 — 2026-06-12 사고

작업자가 O8000의 중간 줄에 커서를 두고 START → 수량(#120) 설정 줄이 실행되지 않음 → 총길이 #100이 0.1로 계산 → 지난 판에서 남아 있던 스위치 변수가 길이검사를 무력화 → G10 L2로 원점이 척 코앞에 잡힘 → 공구가 척으로 돌진.

근본 원인: FANUC 공통변수(#100번대·#500번대)는 프로그램이 끝나도, 리셋해도 값이 남는다. 중간에서 시작하면 기계는 "지난 판의 찌꺼기 값"으로 그냥 달리며, 기계 스스로는 정상시작인지 중간시작인지 구분할 방법이 없다.

2. 원리 — 샌드위치 통행권

구분 수단을 우리가 변수로 심는다. 핵심은 "두 줄이 모두, 순서대로 실행됐음을 산수로 증명하게 만드는 것."

O0852 (메인)
├─ N10 첫머리:  #149 = 852        ← 🎫 열쇠 발급
│   ... 입력 ~30줄 ...
│   ... 검증 ~40줄 (-9999 체크) ...
├─ 검증 끝:     #148 = #149 + 1   ← ✅ 도장 (= 853)
└─ M98 P9001
     └─ O9001 머리:  IF [#148 EQ 853] → 통과
                      아니면 → 알람 25 (RESTART FROM TOP)
                      통과 즉시 #148=0, #149=0   ← 🔥 표 회수 (1회용)

열쇠와 도장 사이에 입력부와 검증 전체가 끼어 있으므로, 표가 유효하다 = 헤더를 처음부터 끝까지 통과했다는 증명이 된다.

3. 왜 뚫리지 않는가 — 경우의 수

① 가공 직전(N20 등)에 커서 두고 시작

열쇠도 도장도 안 지나감. #148은 지난 판에서 회수돼 0. 검문 0 ≠ 853 → 알람 25.

② 도장 줄 바로 위에서 시작 (교묘한 경우)

도장 줄은 실행되지만 열쇠를 안 지나 #149=0 → 도장 = 0+1 = 1 ≠ 853 → 알람 25.
도장을 상수 #148=853이 아니라 수식 #148=#149+1로 쓰는 이유가 이것 — 도장이 열쇠에서 파생되므로 빵 두 장을 둘 다, 이 순서로 지나야만 유효한 표가 만들어진다.

③ 정상 완주 후 다음 판을 중간부터 시작

검문 통과 순간 표를 0으로 회수(1회용)했으므로 또 걸린다. 매 판마다 새 표가 필요.

④ 다른 프로그램의 표로 통과 시도

프로그램마다 키값이 다르다(아래 표). 6호기 표(#148=8001)로는 O9001(853 요구) 불통 — 교차 누수 방지.

5. 개찰구 용접 — NE9 잠금

표 검사만으로는 부족하다 — 작업자가 검문 코드 자체를 지우면 끝이므로. 그래서 로직/서브를 전부 9000번대 번호로 모으고 파라미터 3202#4 (NE9) = 1을 켠다 → O9000~O9999 전체가 화면에서 숨겨지고 편집 금지.

  • O0400 계열의 서브 번호를 O0410/O7001~7005 → O9020~9025로 옮긴 이유가 이것
  • O0852 계열은 처음부터 O9001~9003이라 번호 이전 불필요
NE8(3202#0)은 절대 켜지 말 것 — 8000번대까지 잠겨 O8000 메인을 못 만지게 된다. 잠금 후 파라메터 쓰기 0 복귀.

6. 함께 들어간 보조 가드

  • #120 절대 가드: 수량이 0/빈값이면 알람 20 — 다른 스위치로도 못 끔 (O8000·O0400)
  • #124 1회용화 (O0400): MANUAL MODE가 켜진 채 방치되지 않도록 사이클 끝에 자동 0 복귀
  • -9999 전수검증 (O0852): 시작 시 전 변수를 -9999로 리셋 → 입력 누락이 하나라도 있으면 해당 번호 알람
  • #130 머신셀렉트 (O0852): 등록 안 된 호기번호면 알람 99. 단, 다른 호기 번호를 잘못 넣는 것은 못 잡는다 — 세팅 체크리스트에서 "#130 = 지금 서 있는 호기 번호" 확인 필수
