# 2호기 O0300 사진 등록

사용자가 바탕화면의 2호기 O0300 폴더로 제공한 CNC 사진 5장을 등록했다. 메인은 O0300, 서브는 O0310이다. 원본 NC 파일은 제공되지 않았다. 사진 2의 #513 계산 줄 오른쪽 끝은 잘려 있으므로 전사 코드에 미확인 표시를 남겼으며 다른 프로그램을 바탕으로 복원하지 않았다.

2호기 현재 배정은 O0300으로 변경하고, 이전 O0400은 해당 호기의 기존 배정 자료에 보관한다. 13호기의 O0400 배정은 유지한다. 완성 NC 다운로드 및 시뮬레이션은 제공하지 않고 사진, 전사 TXT, 면취 비교를 연결한다.

scripts/build_o0300.py에 사진별 전사와 비교표가 있다. 면취 속도 계산은 사진 전사의 메인 설정과 programs/o0600/O0600.nc를 읽고, 비교용 5호기 블록은 O9050.nc에서 추출한다. 사진은 programs/o0300/photos에 원본 바이트를 보존하며 provenance.json에 SHA-256을 기록한다.

python -X utf8 scripts/build_o0300.py 로 화면과 UTF-8 BOM/CRLF 전사 TXT를 생성한다. 2호기의 F160 대 5호기의 F144 차이는 약 11.1%이고, 명령상 Z 2mm의 이상적인 이송 시간은 0.750초 대 0.833초다. 가감속·급속·공압·M코드 완료 대기·선택정지를 포함한 실기 사이클 시간은 아니다.

사용자 지시: 로컬에 등록·검증하며 GitHub Pages 푸시는 사용자가 명시적으로 요청할 때까지 하지 않는다. 기존 5호기 가공 프로그램은 이번 비교 작업에서 수정하지 않는다.

추가 확인: 사용자는 실제 장비의 선택정지가 OFF라고 밝혔다. 선택정지 기능 자체에 의한 정지는 제외하되, 이것만으로 M01이 포함된 블록의 처리 시간 영향까지 없다고 단정하지 않는다.

O8000 추가 비교: o8000.html의 src-O8000/src-O9010 원문을 읽어 3개 프로그램 비교표와 코드 발췌를 생성한다. O8000도 1600 × 0.09 = 144 mm/min, Z 2 mm 면취, W10/M55 복귀이며 묶음 N320뿐 아니라 잔량 N420도 확인한다. 면취 후 계산·M01·복귀 M55 재지시는 원문에 존재한다. 5호기의 계산 위치 재배치와 T3 추가 X 급속 블록은 별도 차이로 표시한다.

앱의 3·6호기 O8000 링크는 6호기 기준 공통 원문이다. 3호기 CNC에서 별도로 가져온 코드·설정으로 간주하지 않는다. 앱 M코드 표 기준으로 3호기는 에어 M08/M09, M03 역회전이고 6호기는 M51/M52, M03 정회전이다. 사진에서 잘린 2호기 #513 줄은 O8000과 닮았어도 채워 넣지 않는다.

검증: python -u -X utf8 tests/verify_o0300_web.py 로 세 프로그램 코드 발췌, 면취 이송값, 3·6호기 원문 구분, 호기별 비교 링크, 휴대폰·다운로드·오프라인 동작을 확인한다.

사용자 추가 관찰: 2호기를 제외한 3·5·6호기는 약 0.8초 멈칫 후 절단으로 넘어간다. T2는 이미 들어가 있고 공구대가 멈춘 상태다. 시간은 사용자 추정 관찰값으로 계측 검증값이 아니다.

진단을 이송값 비교에서 복귀 후 정지로 옮겼다. F144로 Z 2mm를 이동하는 0.833초와 사용자 관찰의 정지 0.8초를 구분한다. 5호기만의 추가 X 블록이나 계산 재배치는 3·6호기와의 공통 원인으로 단정하지 않는다.

2026-09-11 M01 시험 결과: 사용자가 실제 5호기에서 M01을 삭제했으나 아무 변화가 없다고 확인했다. 기존 로컬 화면·TXT의 시험 전 안내를 삭제 결과로 교체했다. 5호기에서 M01 하나가 원인이라는 가설은 지지되지 않는다. 3·6호기의 M01 삭제 시험은 보고되지 않았다.

사용자가 좁힌 구간은 G00 W10. M55; 다음 #521 증가 → N330 → #516 계산 → #522 증가 → G00 X-[#503] T03;이다. 마지막 X 줄에는 T03만 있고, S#516 M03는 그 뒤 Z 이동 다음 X 접근 줄에 있다고 추가 확인했다. 이는 계산을 미리 배치하고 첫 X 줄에 S/M03를 합친 현재 앱·바탕화면 등록본과 다르며, 이전 원문의 순서와 대응한다. 현재 등록본을 실제 CNC에 모두 적용했다고 간주하지 않는다. 전달한 코드의 기호를 이전 원문과 대조해 정리했으며 CNC 추출 파일로 표시하지 않는다.

세 계산식은 위치/회전수 값 준비이며 대기시간 지정 명령은 아니다. 계산 처리, W10/M55 완료 확인, 첫 X/T03 처리 중 어디서 지연되는지는 미확인이다. 첫 X 줄에 없는 S/M03를 해당 줄의 지연 원인으로 설명하지 않는다. T03을 회전 공구대 교환으로 해석하거나, 복귀 동작이 끝났다는 관찰만으로 제어기의 완료 확인까지 끝났다고 간주하지 않는다. 2호기와 O8000도 후퇴 뒤 계산 및 T03이 있으므로 이 명령들의 존재만으로 원인을 단정하지 않는다.

이번 변경은 로컬 진단 기록·비교표·TXT·캐시에 한정한다. 가공 NC와 CNC 설정은 변경하지 않았고 GitHub Pages 푸시도 하지 않았다.

2026-09-11 추가 확인: 2호기는 현대위아 FANUC i Series Smart Plus, 3호기는 현대위아 FANUC Series 0i-TC, 5·6호기는 FANUC Series 0i-TD다. Smart Plus의 내부 FANUC 세부 모델은 미확인이다. 명령 처리 성능·선행 해석·기계 측 완료 처리 차이를 검토할 단서로 기록하되 모델명만으로 세 계산식이 0.8초를 소비한다고 단정하지 않는다. 전체 호기와 시리즈 특징은 `machines.html`에 등록했다.

[FANUC 0i-D 유지보수 매뉴얼 B-64305EN/01 공개 사본](https://www.scribd.com/document/478553866/B-64305EN-01-Maintenance-Manual-0i-D)의 적용 모델 표, §1.3, §1.4를 확인했다. 상태표시 FIN은 PMC의 보조기능 완료 대기이며, 진단 0의 INPOSITION CHECK는 축 위치 도착 확인 상태다. 두 항목을 정지 구간과 대조하는 읽기 전용 안내를 로컬 화면·TXT에 추가했다. FIN만으로 M55와 T03 중 어느 명령인지 구분하지 않으며, 두 표시가 없다고 계산 지연으로 확정하지 않는다. 파라미터·진단값·PMC 변경 지침은 제공하지 않는다.
